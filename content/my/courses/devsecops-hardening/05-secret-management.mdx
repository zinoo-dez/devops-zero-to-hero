# Secret Management with HashiCorp Vault & Sealed Secrets

Standard Kubernetes မှာ `Secret` object က **encrypted မလုပ်ထားပါဘူး** — Base64 နဲ့ encode လုပ်ထားရုံပဲ ဖြစ်ပါတယ် (`echo "password" | base64`)။ သင့်ရဲ့ Git repository ကို ဖတ်နိုင်တဲ့သူ ဒါမှမဟုတ် `kubectl` access ရှိတဲ့ ဘယ်သူမဆို ဒါကို အလွယ်တကူ decode လုပ်နိုင်ပါတယ်-

```bash
$ echo "U3VwZXJTZWNyZXRQYXNzd29yZDEyMw==" | base64 -d
SuperSecretPassword123
```

Standard Kubernetes Secrets တွေ ဒါမှမဟုတ် `.env` file တွေကို Git ထဲ ဘယ်တော့မှ commit မတင်ပါနဲ့။ ဒီ lesson မှာတော့ **Bitnami Sealed Secrets** နဲ့ **HashiCorp Vault** တို့ကို သုံးပြီး production secret management ကို ကျွမ်းကျင်အောင် လုပ်သွားမှာ ဖြစ်ပါတယ်။

---

## Approach 1: Bitnami Sealed Secrets (GitOps အတွက် အသင့်တော်ဆုံး)

Sealed Secrets က **Asymmetric Cryptography** (Public/Private Key Encryption) ကို အသုံးပြုပါတယ်-
1. **Public Key (Local Developer)**: Public Git မှာ commit တင်ဖို့ 100% စိတ်ချရတဲ့ `SealedSecret` manifest အဖြစ် secrets တွေကို *encrypt* လုပ်ဖို့ပဲ သုံးနိုင်ပါတယ်။
2. **Private Key (Cluster Only)**: Kubernetes cluster controller ရဲ့ အတွင်းဘက်မှာပဲ သီးသန့်တည်ရှိပြီး encrypted ဖြစ်နေတဲ့ secret ကို memory ထဲမှာ native Kubernetes Secret အဖြစ် ပြန်ပြီး decrypt လုပ်ပေးပါတယ်။

```mermaid
flowchart LR
    Dev["Developer with raw password"] -->|kubeseal with Public Key| SS["SealedSecret.yaml (Encrypted Ciphertext)"]
    SS -->|Safe to commit| Git["Public GitHub Repository"]
    Git -->|ArgoCD sync| K8s["Kubernetes Cluster"]
    K8s --> Controller["Sealed Secrets Controller
(Has Private Key)"]
    Controller -->|Decrypts| Secret["Native K8s Secret (In-Memory)"]
    Secret --> Pod["Application Pod"]
```

### Hands-On: SealedSecret တစ်ခု ဖန်တီးခြင်း
```bash
# 1. Temporary local secret တစ်ခု ဖန်တီးပါ (ဒါကို Git ထဲ လုံးဝ commit မတင်ပါနဲ့)
kubectl create secret generic db-credentials   --from-literal=password='SuperSecureDBPassword2026!'   --dry-run=client -o yaml > secret.yaml

# 2. Cluster ရဲ့ public encryption key ကိုသုံးပြီး secret ကို seal လုပ်ပါ
kubeseal --format=yaml < secret.yaml > sealed-secret.yaml

# 3. Plain-text secret file ကို ဖျက်ပစ်ပါ!
rm secret.yaml
```

အခု `sealed-secret.yaml` ကို စစ်ကြည့်ရအောင်-
```yaml
apiVersion: bitnamia.com/v1alpha1
kind: SealedSecret
metadata:
  name: db-credentials
  namespace: production
spec:
  encryptedData:
    password: AgBy19aX0zLk...[COMPLETELY ENCRYPTED CIPHERTEXT]...8qPw==
```

ဒီ file က သင့်ရဲ့ public Git repository ထဲမှာ commit တင်ဖို့ **100% စိတ်ချရပါတယ်**။

## Approach 2: HashiCorp Vault (Enterprise Dynamic Secrets)

**HashiCorp Vault** ကတော့ centralized secret management အတွက် industry standard ဖြစ်ပြီး **Dynamic Secrets** တွေကို (1 နာရီအတွင်း automatically သက်တမ်းကုန်မယ့် unique database credentials တွေကို instant generate လုပ်ပေးတာမျိုး) ပံ့ပိုးပေးပါတယ်။

```mermaid
flowchart LR
    App["Application Pod"] -->|1. Authenticate with K8s ServiceAccount| Vault["HashiCorp Vault Server"]
    Vault -->|2. Verify Token with K8s API| K8s["Kubernetes Control Plane"]
    Vault -->|3. Dynamically generate short-lived DB user| DB[("PostgreSQL Database")]
    Vault -->>App: 4. Returns credentials (TTL: 1 Hour)
```

### Vault Dynamic Secrets ရဲ့ အကျိုးကျေးဇူးများ:
1. **Static Passwords မရှိခြင်း**: Application တစ်ခုက တောင်းဆိုမှသာ passwords တွေ ဖြစ်ပေါ်လာပါတယ်။
2. **Automated Revocation**: Pod သေသွားတဲ့အခါ Vault က database ထဲက user ကို automatically ဖယ်ရှားပေးပါတယ်။
3. **Audit Trail**: Secret ဝင်ရောက်သုံးစွဲမှုတိုင်းကို တောင်းဆိုတဲ့ pod ရဲ့ identity နဲ့တကွ log မှတ်ထားပါတယ်။
