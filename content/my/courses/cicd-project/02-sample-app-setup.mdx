# Creating the Application

သင်သည် PostgreSQL database နှင့် ချိတ်ဆက်ထားသော လက်တွေ့ကျကျ Next.js 14 application တစ်ခုကို တည်ဆောက်မည်ဖြစ်သည်။ ဤရည်ရွယ်ချက်သည် အရုပ်ဆန်ဆန် "Hello World" တစ်ခုမျှ မဟုတ်ပါ — ၎င်းသည် မှန်ကန်သော connection pooling ပါဝင်သော၊ Kubernetes probes များအသုံးပြုသည့် health check endpoint ပါဝင်သော၊ တကယ့် CRUD API နှင့် ဒေတာများကို ပြသပေးသော frontend ပါဝင်သော production-quality app တစ်ခု ဖြစ်သည်။

ဤ app သည် ဤ course တစ်ခုလုံးအတွက် သင် အလိုအလျောက် deploy လုပ်မည့် app ဖြစ်လာမည်ဖြစ်သည်။

## Why Next.js 14 with the App Router?

App Router (Next.js 13 တွင် စတင်မိတ်ဆက်ခဲ့သည်) သည် ယခုအခါ production standard ဖြစ်လာသည်။ ဤ capstone အတွက် ၎င်းကို မှန်ကန်သော ရွေးချယ်မှုဖြစ်စေသည့် အချက်များမှာ အောက်ပါအတိုင်းဖြစ်သည်-

| Feature | Benefit |
|---------|---------|
| **Server Components** | Data fetching ကို server ပေါ်တွင် လုပ်ဆောင်သည် — initial page load အတွက် browser မှ API calls ခေါ်ဆိုရန် မလိုပါ |
| **API Routes** | `/api/*` routes များကို serverless-style handlers များအနေဖြင့် လုပ်ဆောင်သည် — သီးသန့် Express server လိုအပ်ချက်မရှိပါ |
| **Built-in TypeScript** | Frontend နှင့် API code နှစ်ခုလုံးတွင် Type safety ကို ရရှိစေသည် |
| **`output: 'standalone'`** | အနည်းဆုံး Node.js server bundle ကို ဖန်တီးပေးသည်၊ multi-stage Docker builds များအတွက် အထူးသင့်လျော်သည် |
| **Edge-compatible** | အနာဂတ်တွင် လိုအပ်ပါက edge runtimes များတွင်လည်း Run နိုင်သည် |

## Step 1: Initialize the Project

```bash
# Create the project (--app enables the App Router)
npx create-next-app@latest capstone-app \
  --typescript \
  --eslint \
  --tailwind \
  --app \
  --no-src-dir \
  --import-alias "@/*"

cd capstone-app
```

Flag တစ်ခုချင်းစီ၏ လုပ်ဆောင်ချက်များ-
- `--typescript` — ပထမနေ့မှစ၍ TypeScript ကို အသုံးပြုခြင်း၊ နောက်ပိုင်းတွင် migration လုပ်ရသည့် ဒုက္ခမရှိတော့ပါ
- `--eslint` — CI pipeline lint step အတွက် လိုအပ်သော ESLint config အဆင်သင့်ဖြစ်နေခြင်း
- `--tailwind` — Utility-first CSS၊ မြန်ဆန်သော UI အလုပ်များအတွက် အလွန်ကောင်းမွန်ခြင်း
- `--app` — App Router ကို အသုံးပြုခြင်း (legacy `pages/` directory ကို မသုံးပါ)
- `--no-src-dir` — ဖိုင်များကို `src/` အောက်တွင် ထည့်မထားဘဲ root `app/` directory ထက်တွင်သာ ထားရှိခြင်း

## Step 5: The Database Connection Pool

Connection pool တစ်ခုသည် query တစ်ခုချင်းစီအတွက် TCP connection အသစ် အမြဲဖန်တီးနေမည့်အစား database connections များကို ပြန်လည်အသုံးပြုသည်။ ၎င်းသည် performance အတွက် အရေးကြီးသည် — PostgreSQL connection တစ်ခု တည်ဆောက်ရန် ~5-50ms ကြာမြင့်သည်။ Load များနေချိန်တွင် request တစ်ခုချင်းစီအတွက် connection အသစ် ဖန်တီးနေခြင်းသည် ဆိုးရွားသော ရလဒ်ကို ဖြစ်စေနိုင်င်သည်။

```typescript
// lib/db.ts
import { Pool } from "pg";

// Using a singleton pattern to prevent multiple pool instances during
// Next.js hot-reload in development (which re-imports modules)
declare global {
  // eslint-disable-next-line no-var
  var _pgPool: Pool | undefined;
}

function createPool(): Pool {
  return new Pool({
    connectionString: process.env.DATABASE_URL,
    max: 10,                   // Maximum connections in the pool
    min: 2,                    // Keep at least 2 connections open
    idleTimeoutMillis: 30000,  // Close idle connections after 30s
    connectionTimeoutMillis: 5000,  // Fail fast if DB is unreachable
    // SSL configuration for production (many managed DBs require it)
    ssl: process.env.NODE_ENV === "production"
      ? { rejectUnauthorized: true }
      : false,
  });
}

// Singleton: reuse pool in development (hot-reload), create fresh in production
const pool = global._pgPool ?? createPool();

if (process.env.NODE_ENV !== "production") {
  global._pgPool = pool;
}

export default pool;
```

<Callout type="warning" title="Connection Pool Sizing">
Kubernetes replicas 3 ခု ရှိပြီး တစ်ခုချင်းစီတွင် `max: 10` ရှိပါက, သင်သည် တစ်ချိန်တည်းတွင် connections 30 အထိ ဖွင့်လှစ်နိုင်သည်။ သင်၏ PostgreSQL `max_connections` setting (default: 100) သည် `replicas × pool.max` ထက် ပိုများကြောင်း သေချာအောင် လုပ်ပါ။ Lesson 7 တွင်, သင်သည် PgBouncer ကို configure လုပ်မည် သို့မဟုတ် replica တစ်ခုချင်းစီအတွက် `max: 5` ကို အသုံးပြုမည် ဖြစ်သည်။
</Callout>

## Step 6: Health Check API Route

Kubernetes သည် **liveness** နှင့် **readiness** probes များအတွက် `/api/health` endpoint ကို အသုံးပြုသည်-

- **Liveness probe**: "ဤ pod အသက်ရှင်နေသေးသလား?" — 3 ကြိမ် ဆက်တိုက် မအောင်မြင်ပါက K8s သည် pod ကို restart ချသည်
- **Readiness probe**: "ဤ pod သည် traffic ကို လက်ခံရန် အဆင်သင့်ဖြစ်ပြီလား?" — မအောင်မြင်ပါက K8s သည် ၎င်းကို Service endpoints များမှ ဖယ်ရှားသည်

သင်၏ health check သည် "Node process run နေသလား" ဆိုရုံသာမက တကယ့် system readiness ကို စစ်ဆေးသင့်သည်-

```typescript
// app/api/health/route.ts
import { NextResponse } from "next/server";
import pool from "@/lib/db";

export const dynamic = "force-dynamic"; // Never cache this endpoint

interface HealthStatus {
  status: "ok" | "degraded" | "error";
  timestamp: string;
  uptime: number;
  db: {
    status: "connected" | "disconnected";
    latencyMs?: number;
  };
  version: string;
}

export async function GET() {
  const startTime = Date.now();

  try {
    // Measure database query latency
    const dbStart = Date.now();
    await pool.query("SELECT 1");
    const dbLatency = Date.now() - dbStart;

    const body: HealthStatus = {
      status: "ok",
      timestamp: new Date().toISOString(),
      uptime: process.uptime(),
      db: {
        status: "connected",
        latencyMs: dbLatency,
      },
      version: process.env.APP_VERSION ?? "unknown",
    };

    return NextResponse.json(body, {
      status: 200,
      headers: {
        "Cache-Control": "no-store",
      },
    });
  } catch (error) {
    const body: HealthStatus = {
      status: "error",
      timestamp: new Date().toISOString(),
      uptime: process.uptime(),
      db: {
        status: "disconnected",
      },
      version: process.env.APP_VERSION ?? "unknown",
    };

    console.error("[health] Database connectivity check failed:", error);

    return NextResponse.json(body, {
      status: 503, // Service Unavailable — K8s interprets this as unhealthy
    });
  }
}
```

## Step 7: Items CRUD API

```typescript
// app/api/items/route.ts
import { NextRequest, NextResponse } from "next/server";
import pool from "@/lib/db";

// Run database migrations on first request
// In production, use a proper migration tool (e.g., Flyway, golang-migrate)
let initialized = false;

async function ensureTable() {
  if (initialized) return;
  await pool.query(`
    CREATE TABLE IF NOT EXISTS items (
      id        SERIAL PRIMARY KEY,
      name      TEXT        NOT NULL CHECK (length(name) > 0 AND length(name) <= 200),
      created_at TIMESTAMPTZ DEFAULT NOW()
    )
  `);
  initialized = true;
}

// GET /api/items — List all items (newest first)
export async function GET() {
  try {
    await ensureTable();
    const result = await pool.query(
      "SELECT id, name, created_at FROM items ORDER BY created_at DESC LIMIT 100"
    );
    return NextResponse.json({
      items: result.rows,
      count: result.rowCount,
    });
  } catch (error) {
    console.error("[items GET]", error);
    return NextResponse.json({ error: "Failed to fetch items" }, { status: 500 });
  }
}

// POST /api/items — Create a new item
export async function POST(req: NextRequest) {
  try {
    await ensureTable();

    const body = await req.json();

    // Input validation — never trust user input
    if (!body.name || typeof body.name !== "string") {
      return NextResponse.json(
        { error: "name is required and must be a string" },
        { status: 400 }
      );
    }

    const name = body.name.trim();

    if (name.length === 0 || name.length > 200) {
      return NextResponse.json(
        { error: "name must be between 1 and 200 characters" },
        { status: 400 }
      );
    }

    const result = await pool.query(
      "INSERT INTO items (name) VALUES ($1) RETURNING id, name, created_at",
      [name]  // Parameterized query — prevents SQL injection
    );

    return NextResponse.json(result.rows[0], { status: 201 });
  } catch (error) {
    console.error("[items POST]", error);
    return NextResponse.json({ error: "Failed to create item" }, { status: 500 });
  }
}
```

```typescript
// app/api/items/[id]/route.ts
import { NextRequest, NextResponse } from "next/server";
import pool from "@/lib/db";

// DELETE /api/items/:id — Delete an item by ID
export async function DELETE(
  _req: NextRequest,
  { params }: { params: { id: string } }
) {
  const id = parseInt(params.id, 10);

  if (isNaN(id)) {
    return NextResponse.json({ error: "Invalid ID" }, { status: 400 });
  }

  try {
    const result = await pool.query(
      "DELETE FROM items WHERE id = $1 RETURNING id",
      [id]
    );

    if (result.rowCount === 0) {
      return NextResponse.json({ error: "Item not found" }, { status: 404 });
    }

    return new NextResponse(null, { status: 204 });
  } catch (error) {
    console.error("[items DELETE]", error);
    return NextResponse.json({ error: "Failed to delete item" }, { status: 500 });
  }
}
```

```typescript
// components/ItemList.tsx
"use client";

import { useState, useEffect } from "react";

interface Item {
  id: number;
  name: string;
  created_at: string;
}

export function ItemList() {
  const [items, setItems] = useState<Item[]>([]);
  const [input, setInput] = useState("");
  const [loading, setLoading] = useState(false);

  async function fetchItems() {
    const res = await fetch("/api/items");
    const data = await res.json();
    setItems(data.items ?? []);
  }

  async function addItem() {
    if (!input.trim()) return;
    setLoading(true);
    await fetch("/api/items", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ name: input }),
    });
    setInput("");
    await fetchItems();
    setLoading(false);
  }

  async function deleteItem(id: number) {
    await fetch(`/api/items/${id}`, { method: "DELETE" });
    setItems((prev) => prev.filter((i) => i.id !== id));
  }

  useEffect(() => {
    fetchItems();
  }, []);

  return (
    <div>
      <div className="flex gap-2 mb-6">
        <input
          className="flex-1 border rounded px-3 py-2 text-sm"
          placeholder="New item name..."
          value={input}
          onChange={(e) => setInput(e.target.value)}
          onKeyDown={(e) => e.key === "Enter" && addItem()}
        />
        <button
          onClick={addItem}
          disabled={loading}
          className="bg-blue-600 text-white px-4 py-2 rounded text-sm hover:bg-blue-700 disabled:opacity-50"
        >
          {loading ? "Adding..." : "Add Item"}
        </button>
      </div>

      {items.length === 0 ? (
        <p className="text-gray-400 text-sm">No items yet. Add one above!</p>
      ) : (
        <ul className="space-y-2">
          {items.map((item) => (
            <li key={item.id} className="flex items-center justify-between border rounded px-3 py-2">
              <span className="text-sm">{item.name}</span>
              <button
                onClick={() => deleteItem(item.id)}
                className="text-red-500 text-xs hover:underline"
              >
                Delete
              </button>
            </li>
          ))}
        </ul>
      )}
    </div>
  );
}
```

import { describe, it, expect, vi, beforeEach } from "vitest";

// Mock the database pool
vi.mock("@/lib/db", () => ({
  default: {
    query: vi.fn().mockResolvedValue({ rows: [{ "?column?": 1 }] }),
  },
}));

describe("/api/health", () => {
  it("returns 200 when database is reachable", async () => {
    const { GET } = await import("@/app/api/health/route");
    const response = await GET();
    const body = await response.json();

    expect(response.status).toBe(200);
    expect(body.status).toBe("ok");
    expect(body.db.status).toBe("connected");
  });

  it("returns 503 when database is unreachable", async () => {
    const pool = (await import("@/lib/db")).default;
    vi.mocked(pool.query).mockRejectedValueOnce(new Error("Connection refused"));

    const { GET } = await import("@/app/api/health/route");
    const response = await GET();
    const body = await response.json();

    expect(response.status).toBe(503);
    expect(body.status).toBe("error");
    expect(body.db.status).toBe("disconnected");
  });
});

## Troubleshooting Common Issues

### "Can't connect to database" locally
```bash
# Check if the postgres container is healthy
docker compose -f docker-compose.dev.yml ps
# LOOK FOR: Status = healthy (not starting)

# Check postgres logs
docker compose -f docker-compose.dev.yml logs db

# Connect manually to verify
docker compose -f docker-compose.dev.yml exec db \
  psql -U appuser -d capstone -c "SELECT 1"
```

### "Module not found: @/lib/db"
```bash
# Ensure your tsconfig.json has the path alias
cat tsconfig.json | grep paths
# Should see: "@/*": ["./*"]

# Ensure next.config.ts has the same alias
# create-next-app adds this automatically with --import-alias "@/*"
```

### Hot-reload not working in Docker
```bash
# The volume mount approach in docker-compose.dev.yml should handle this.
# If not, ensure WATCHPACK_POLLING=true is set:
environment:
  WATCHPACK_POLLING: "true"
```
